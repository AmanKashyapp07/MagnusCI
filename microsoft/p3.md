## 3. Visual Flowcharts: Fork Bomb & OOM Killer Defense

### Defense A: Fork Bomb Attack Mitigation
```
 [ MALICIOUS USER SCRIPT: :(){ :|:& };: ]
                         │
                         ▼
  Process attempts recursive fork() calls in milliseconds
                         │
                         ▼
  PIDs inside container hit cgroup ceiling: PidsLimit = 100
                         │
                         ▼
  Linux kernel rejects subsequent clone() and fork() system calls
  Error returned: "Resource temporarily unavailable"
                         │
                         ▼
  Host operating system, worker daemon, and Docker daemon remain 100% stable!
```

### Defense B: Memory Leak & Kernel OOM Event
```
 [ MEMORY EXHAUSTION: Script allocates 2GB in a 1GB container ]
                         │
                         ▼
  Container RSS memory exceeds cgroup limit: Memory = 1,073,741,824 bytes
                         │
                         ▼
  Linux Kernel Out-of-Memory (OOM) Killer intercepts event
                         │
                         ▼
  Sends SIGKILL specifically to container process group
                         │
                         ▼
  Container exits with Exit Code 137 (128 + 9)
                         │
                         ▼
  Worker daemon receives code 137, logs "Process killed: Memory limit exceeded"
  Host node memory remains completely untouched!
```

## 4. Sandboxing & Isolation Failure Matrix

| Threat / Failure | Mechanism | System Defense | Host / Pipeline Outcome |
| :--- | :--- | :--- | :--- |
| **Path Traversal / Escape** | Symlink to `../../../../etc/shadow` | Linux Mount Namespaces | Resolves relative to container root (`/`); host filesystem invisible. |
| **Privilege Escalation** | Setuid binary or `sudo` exploit | `--security-opt=no-new-privileges` + `--cap-drop=ALL` | Kernel ignores setuid bit; execution remains non-root (`UID 1001`). |
| **Fork Bomb** | `:(){ :|:& };:` process spam | `PidsLimit: 100` | Kernel blocks process creation past 100; script halts with error. |
| **Memory Exhaustion** | Memory leak or infinite allocation | `Memory: 1073741824` (1GB) | Kernel OOM killer terminates container (code 137); host unaffected. |
| **CPU Starvation** | `while true` infinite CPU loop | `CpuQuota: 100000` / `CpuPeriod: 100000` | Kernel throttles process to exactly 1 vCPU; other pods run smoothly. |
| **Host Socket Exposure** | Untrusted code reaching Docker socket | Socket is **never** mounted into sandbox container | User code cannot issue Docker API calls or spawn privileged containers. |

## 5. Rapid Interview Talking Points (60 Seconds)

- **Strict Sandbox Boundaries:** Containers run with 1GB RAM ceilings, 1.0 CPU quota, and 100 PIDs limits to isolate untrusted user scripts from the host.
- **Defense in Depth:** Dropped all Linux capabilities (`CapDrop: ALL`), disabled privilege escalation (`no-new-privileges`), and executed under non-root UID `1001`.
- **Dual-Tier Storage:** Workspaces prioritize Linux tmpfs (`/dev/shm`) for 3x I/O speedup, falling back to NVMe `/tmp` if RAM free space drops below 256MB.
- **Senior Reflection:** Docker socket access on the worker daemon is our single largest attack surface; enterprise evolution requires migrating to unprivileged Kubernetes Jobs or AWS Firecracker microVMs.
