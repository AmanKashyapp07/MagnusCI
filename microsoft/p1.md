## 1. Multi-Stage Pipeline DAG Architecture

```
┌──────────────────────────────────────────────────────────────────────────────────────────────────┐
│                             MULTI-STAGE PIPELINE DAG EXECUTION                                   │
└──────────────────────────────────────────────────────────────────────────────────────────────────┘

                        ┌──────────────┐
                   ┌───►│  lint-code   │────────┐
                   │    │ (ESLint: 5s) │        │
  [ Ingress Spec ] │    └──────────────┘        │
   magnus-ci.json  │      (PARALLEL WAVE)       ▼
         ──────────┤                    ┌──────────────┐       ┌──────────────┐
                   │    ┌──────────────┐│ build-bundle │──────►│ deploy-prod  │
                   └───►│  unit-test   ││ (Webpack: 15s│       │ (Deploy: 10s)│
                        │ (Vitest: 12s)│└──────────────┘       └──────────────┘
                        └──────────────┘        ▲
                               │                │
                               └────────────────┘
```

- Stages declare dependencies in `magnus-ci.json`: e.g. `"build": { "dependsOn": ["lint", "test"] }`.
- Independent root stages (`in_degree == 0`) launch concurrently in parallel.
- Downstream stages unblock the instant all upstream parents transition to `SUCCESS`.

## 2. Algorithm Comparison: Scheduling & Cycle Detection

| Feature / Metric | Kahn's Algorithm (BFS) | Tarjan's / DFS Algorithm | Naive Sequential Execution |
| :--- | :--- | :--- | :--- |
| **Time Complexity** | **$O(V + E)$** Linear | **$O(V + E)$** Linear | $O(V)$ (ignores edges) |
| **Space Complexity**| **$O(V)$** (in-degree array + queue) | **$O(V)$** (recursion call stack) | $O(1)$ |
| **Algorithm Nature**| **BFS** (Queue-based in-degree tracking)| **DFS** (Recursion stack tracking) | Procedural loop |
| **Cycle Detection** | **Count check:** `processedCount < V` | **Back-edge check:** `recStack.has(node)`| Hangs indefinitely in infinite loop |
| **Stage Ordering**  | Generates static topological sort array | Detects cycles; passes to event loop | Arbitrary array order |
| **Execution Fit**   | Excellent for static batch ordering | **Optimal for fast-fail pre-validation**| Poor (serial bottleneck) |

```

              Compute in-degree for all V vertices
                               │
                               ▼
            Find all vertices with in_degree == 0
                               │
                               ▼
                    Enqueue to Zero-Queue
                               │
             ┌─────────────────┴─────────────────┐
             │                                   │
             ▼                                   ▼
      Queue NOT Empty                      Queue IS Empty
             │                                   │
             ▼                                   ▼
    Pop vertex U from queue             Check: processedCount == V?
    processedCount++                             │
             │                         ┌─────────┴─────────┐
             ▼                         ▼                   ▼

    in_degree[V]--                     │                   │

```

## 4. Reactive Event Loop: `Promise.race()` vs. Wave-Based `Promise.all()`

```
 [ NAIVE WAVE SCHEDULING (Promise.all) ]
  Wave 1: [Lint: 5s] + [Heavy-Test: 60s] ──► Runner idle for 55s waiting for Heavy-Test!
  Wave 2: [Build: 15s] ──► Cannot start until 60s mark! Total: 75s.

 [ MAGNUSCI REACTIVE SCHEDULING (Promise.race) ]
  Time 0s:  Dispatches [Lint: 5s] and [Heavy-Test: 60s] concurrently.
  Time 5s:  Lint finishes! Promise.race() triggers immediately.
            Checks downstream: Does any stage depend ONLY on Lint? If yes, launch NOW!
  Time 60s: Heavy-Test finishes! Unblocks remaining dependent stages.
  RESULT: Eliminates idle runner gaps; pipeline completes at theoretical minimum runtime!
```

## 5. Pipeline Failure Matrix

| Failure Event | Detection Point | System Reaction | User / Host Impact |
| :--- | :--- | :--- | :--- |
| **Cyclic Dependency** (`A -> B -> A`) | Pre-execution (`hasCycle()`) | Throws descriptive cycle error; pipeline aborted before container creation. | **Zero host impact.** Returns HTTP 400 in $< 1\text{ms}$. |
| **Stage Command Failure** (`exit 1`) | Container wait (`container.wait()`) | Stage marked `FAILED`. DAG marks downstream stages `CANCELLED`. | Sibling independent stages complete; build halts cleanly. |
| **Stage Execution Timeout** | Timer race (`setTimeout`) | Container killed (`SIGKILL`); stage marked `TIMED_OUT`. | Prevents hanging user commands from locking worker slots. |
| **Container OOM Crash** (`exit 137`) | Linux kernel cgroup event | Docker daemon emits exit 137. Worker logs OOM diagnostic. | Host RAM protected. Stage fails with memory ceiling notice. |
| **Worker Process Crash** | BullMQ stalled watchdog | Expired Redis lock detected after 300s; job re-queued to active worker. | Build restarted from scratch on healthy worker pod. |

## 6. Rapid Interview Talking Points (60 Seconds)

- **Graph Structure:** Pipelines are directed acyclic graphs declared via JSON. $V$ is stages, $E$ is dependency relationships.
- **Upfront Cycle Check:** Runs Kahn's / DFS cycle validation in $O(V+E)$ time before allocating host workspaces or pulling images.
- **Execution Mechanism:** Rather than rigid sequential waves (`Promise.all`), a reactive event loop (`Promise.race()`) listens for container exits, unblocking ready stages the instant all upstream parents finish.
- **Edge Cases Handled:** Diamond graphs (`A -> B, C -> D`), disjoint parallel stages, fast-failing stages, and container log draining before removal.
