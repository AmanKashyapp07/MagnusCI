## 1. Comparative Log Streaming Protocol Matrix

| Feature / Metric | Server-Sent Events (SSE) | WebSockets (Socket.io / ws) | HTTP Short-Polling (GET /logs) |
| :--- | :--- | :--- | :--- |
| **Directionality** | **Unidirectional** (Server $\rightarrow$ Client) | **Bidirectional** (Full Duplex) | Unidirectional (Client-initiated) |
| **Connection Overhead**| **Minimal** (Single standard HTTP connection)| Low (TCP upgrade handshake) | **Severe** (New TCP/TLS handshake per poll) |
| **Protocol Compatibility**| **100% Native HTTP/2** (Works behind any proxy)| Requires WebSocket proxy pass config | Standard HTTP |
| **Reconnection Model** | **Automatic built-in browser reconnect** | Requires client reconnection logic | N/A |
| **Binary Support**  | UTF-8 text streams only | Binary buffers + UTF-8 text | JSON payloads |
| **Best Fit for CI Logs**| **Ideal for read-only terminal log feeds** | **Ideal if client sends stdin (PTYs)**| Terrible (High latency, high DB IOPS) |

## 4. Log Streaming & Artifact Failure Matrix

| Failure Mode | Root Cause | System Defense | User / Build Outcome |
| :--- | :--- | :--- | :--- |
| **Corrupted Cache Archive** | Partial upload due to worker crash | S3 atomic `PutObjectCommand` commits only on 200 OK. `zstdCache.js` catches decompression errors. | Fails open cleanly; deletes corrupt folder and runs clean `npm ci`. |
| **High-Frequency Log Flood** | Script prints 50,000 lines in a loop | Micro-batching in Node.js worker + 1000ms debounced DB update | Browser UI doesn't freeze; database WAL protected from lockups. |
| **Client Network Drop** | User closes tab or Wi-Fi drops | Dual-path hydration: On reconnect, `GET /api/builds/:id/logs` fetches complete snapshot from DB. | Zero log gaps; terminal catches up to current live output instantly. |
| **MinIO S3 Unreachable** | Object storage pod restart or partition | `try/catch` wrapper in `s3Cache.js` | Cache treated as non-blocking optimization; build proceeds with registry install. |
| **Webhook Ingress Spoofing** | Attacker floods fake push webhooks | `crypto.timingSafeEqual` HMAC-SHA256 signature verification on `req.rawBody` | Discards invalid payloads with HTTP 401 in $< 2\text{ms}$; zero compute wasted. |

## 5. Rapid Interview Talking Points (60 Seconds)

- **Dual-Path Log Hydration:** When a client opens a build, they fetch the historical snapshot via REST, then receive real-time deltas over WebSockets/SSE with zero log loss across reconnects.
- **Backpressure Protection:** In-memory terminal chunk batching and 1000ms database debouncing cut PostgreSQL write IOPS by over 95%.
- **Content-Addressed Cache:** Dependencies are keyed by the SHA-256 hash of `package-lock.json`. Multi-core Zstandard (`zstd -T0 -3`) decompresses at 1.2 GB/s, cutting build startup from 35s down to 2.8s.
- **Fail-Open Design:** A corrupt cache archive or S3 network outage never breaks a pipeline; it degrades gracefully to a standard registry download.
